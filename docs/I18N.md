# Internationalization (i18n)

Termoak apps are multilingual. English is the source language; Spanish is the
first translation. Every app keeps its strings in the format its platform
already understands, so translators can use the usual tools (or a web
platform such as Weblate) and **adding a language never requires code
changes**.

## Where the strings live

| App | Files | Format |
|---|---|---|
| Desktop ([TermoakSSH/desktop](https://github.com/TermoakSSH/desktop)) | `locales/<lang>.json` | flat JSON, loaded with `rust-i18n` |
| Server ([TermoakSSH/server](https://github.com/TermoakSSH/server): emails, plan texts) | `locales/<lang>.json` | flat JSON, loaded with `rust-i18n` |
| Web app built into the server ([TermoakSSH/server](https://github.com/TermoakSSH/server)) | `web/locales/<lang>.json` | flat JSON, fetched by the browser |
| Website ([TermoakSSH/public-web](https://github.com/TermoakSSH/public-web)) | `site/locales/<lang>.json` | flat JSON, fetched by the browser |
| Android ([TermoakSSH/mobile-android](https://github.com/TermoakSSH/mobile-android)) | `app/src/main/res/values[-<lang>]/strings.xml` | Android string resources |
| iOS ([TermoakSSH/mobile-ios](https://github.com/TermoakSSH/mobile-ios)) | `Termoak/Localizable.xcstrings` | Xcode String Catalog |
| CLI | — | English only |

`<lang>` is a BCP 47 code: `en`, `es`, `pt-BR`, `zh-Hans`...

## Conventions

- **Keys** describe where the text is used, not the text itself:
  `hosts.empty.title`, `settings.account.sign_out`. Android uses underscores
  instead of dots (`hosts_empty_title`) because resource names cannot contain
  dots.
- **Placeholders**: `%{name}` in JSON files; `%1$s`, `%2$d`... in Android;
  `%@`, `%lld` in iOS. A translation must keep exactly the same placeholders
  as the English text.
- **Plurals**: JSON uses two keys, `key_one` and `key_other` (and the other
  CLDR categories a language needs: `_zero`, `_two`, `_few`, `_many`); Android
  uses `<plurals>`; iOS uses the catalog's plural variations.
- **Language name**: every JSON file has a `language.name` key with the name of
  the language in that language (`English`, `Español`). Language pickers show it.
- English must contain every key. A missing key in another language falls back
  to English.
- Product names (Termoak, SSH, SFTP...) are not translated.

## Choosing the language

1. The user's choice in the app settings, if any.
2. Otherwise the system (or browser) language, if a translation exists.
3. Otherwise English.

Signed-in clients save the chosen language in the account
(`PATCH /api/v1/me` with `{"locale": "es"}`); the server uses it for emails.
Registration also accepts `locale`.

## Server errors

API errors look like `{"error": {"code": "plan_limit", "message": "..."}}`.
`code` is stable and documented in [API.md](https://github.com/TermoakSSH/server/blob/main/docs/API.md); `message` is English.
Clients show their own translation of `error.<code>` when they have one, and
the English `message` otherwise.

## Adding a language

1. Copy the English file of each app you want to translate (`en.json`,
   `values/strings.xml`) to the new language code (`fr.json`,
   `values-fr/strings.xml`). For iOS, add the language to the String Catalog
   in Xcode, or edit the `localizations` of each key in
   `Localizable.xcstrings`.
2. Translate the values. Do not change the keys or the placeholders.
3. Open a pull request. The new language appears in the language pickers
   automatically.
